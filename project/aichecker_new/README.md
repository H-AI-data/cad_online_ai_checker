# CAD 检测工具：详细使用手册

本页负责输入要求、检查规则、各入口用法、参数、报告与排错；首次安装和基本 API 配置请先看 [交接与快速开始](../../README.md)。这是同一套程序的详细手册，不需要按两份 README 重复安装或重复运行。

**所有运行入口都会自动先执行交接包根目录的 `step检查.py`，无需手动执行；只有前置全部通过，才继续各模块的检查。** 本项目支持三种输入、三个模块、八个维度，每个维度都有独立运行脚本。

## 阅读约定

除另有说明，下方命令的当前目录均为 `project/aichecker_new`，并已按首页激活 Conda 环境、设置 `AI_CHECKER_PYTHON`。命令中的输入路径需要换成实际路径。

完整模块的前置、分类及全部维度在同一次运行中通过后，会自动查重入库；试跑请先按首页创建 `./test_state/step查重.json` 测试副本。单维度不入库，也不能拼接不同运行的通过结果。每次只输入一套资料，不要把多个独立项目的父目录当成一套资料。

输入目录可以包含多层子目录，递归查找大小写不敏感的 STEP/STP、PDF/DXF 和 SolidWorks 文件（最后一个扩展名以 `.sld` 开头）。符号链接、无法确认角色或不完整的输入不会猜测通过。

## 强制 STEP 前置检查

### 自动执行，不是手动准备步骤

总入口 `run.sh`、三个模块的 `run.sh` 和八个维度的独立入口，全部经过同一条前置流程。程序会实际启动 `step检查.py` 检查当前提交，不只是查看是否有同名脚本，也不采用之前手动运行的报告代替本次检查。

| 模块 | 自动送入前置脚本的文件 |
| --- | --- |
| 1 | 输入的单零件 STEP/STP |
| 2 | 总装目录和非标准件目录中的全部 STEP/STP |
| 3 | 输入的总装 STEP/STP |

要求存在实体，且所有实体有效、闭合、体积为正。全部文件前置通过后，才进行几何解析、分类和所选维度检查。任一文件不通过、报错或超时，后续维度不执行，AI 调用为零，最终不会查重入库。

包内 `step检查.py` 是用户原始脚本的原样副本，默认通过相对项目位置定位，不依赖原电脑桌面路径。**正常使用只运行模块命令，不需要先单独运行该脚本；`--llm off` 或单选维度也不会跳过前置检查。**

### 脚本路径、环境与前置报告

如需使用另一位置的同一原始脚本，可在模块命令中追加 `--step-check-script "/原始脚本所在目录/step检查.py"`；这是可选路径覆盖，不是必填参数。

`--step-check-script`、`--freecad-python`、`--freecad-lib` 可指定其他机器上的路径。脚本会核对原始版本SHA256，允许移动原脚本，不允许用任意替代脚本跳过门禁。默认使用当前 Python 和其环境的 `lib`；`--step-timeout 300` 是每个文件的检查超时秒数，`--geometry-timeout 600` 是后续每个 STEP 几何分析超时。超时不会视为通过。

前置报告写入本次输出目录的 `preflight/summary.json`，逐文件报告为 `preflight/step_0001.json` 等，不写进输入目录；如果在调用原脚本之前已被拦截或脚本未能生成报告，可能只有前置汇总原因。先查看 `summary.md` 的前置结果，不要把“后续维度未执行”误认为维度判定已完成。

## 自动分类与检查规则

| 模块 | 输入 | 维度 |
| --- | --- | --- |
| 1 | 一个单零件 STEP/STP、至少一份 SolidWorks 文件和对应 PDF/DXF 工程图 | ①检查三类文件提供情况，再核对 STEP/图纸数量和 AI 内容一致性；②原 cad-complexity-screen 本地筛选复杂特征；③AI确认存在尺寸标注且同一零件至少两个工程视图 |
| 2 | 一个总装子目录、一个非标准件子目录 | ①两目录各自模型/图纸数量一一配套，再AI核对内容；②总装去重≥50种，匹配到总装的非标准件去重占比≥30%；③非标准件均属于总装，几何匹配后AI核对 |
| 3 | 一个多零件总装 STEP/STP，不要求工程图或 SolidWorks | ①STEP/STP 文件提供性检查；②总装去重≥100种；两项均不调用 AI |

单零件/总装依据 STEP 装配结构识别，不以文件名或简单实体数推断。模块二总装目录要求唯一、完整的总装模型；多实体零件不自动当成多个零件。

模块二自动识别名称含“总装/装配/assembly”和“非标准/零件/parts”的两个目录；不明确时指定相对输入目录的路径：

```bash
bash run.sh --input-dir "/路径/一套资料" \
  --assembly-dir "目录A" --nonstandard-dir "目录B" \
  --dedup-registry "./test_state/step查重.json"
```

模块一、二的“数量一一对应”按文件数计算：一份多页 PDF 仍是一个文件；STEP/STP合计与PDF/DXF合计必须相等。提供同一零件的PDF和DXF两个文件也会计为两份图纸。文件名仅影响比较顺序，不能证明内容一致。模块三不执行此项配对。

模块三第一维度仅检查是否提供总装 STEP/STP，提供则“通过”，缺失则中文说明；不要求 PDF/DXF，不渲染工程图，也不调用 AI 判断内容一致性。附带图纸也不做这些检查。原 STEP 有效性前置、装配结构分类及第二维度的100种门槛仍保留，损坏 STEP 不能仅凭扩展名通过整体验收；缺 STEP 时前置即报告不通过，后续维度未执行。

模块一第一维度另要求至少提供一份 SolidWorks 文件：文件最后一个扩展名忽略大小写后以 `.sld` 开头即可，例如 `.sldprt`、`.sldjoin`、`.SLDASM`、`.sld` 等；`零件.sldprt.bak` 不算。只检查是否提供，不解析 SolidWorks 内容，不要求与 STEP 同名，也不核验内容一致性；SolidWorks 文件不参与 STEP/图纸的数量一一对应。缺失则该维度输出中文“不通过”，不调用该维度的图纸一致性 AI。完整运行时其他维度仍照常检查，但本模块不能全部通过或入库。模块二、三不新增此要求；单独运行模块一第二、三维度也不要求提供 SolidWorks。

模块二非标准件由指定子目录确定；标准件是总装去重种类减去匹配到总装的非标准件种类。外来零件不能抬高非标准件占比。重复安装不累计，50/100门槛均按去重种类，使用整数比较30%边界。

复杂特征直接调用 `../scale_cad_v2/cad-complexity-screen/scripts/run.py` 及其原始核心脚本，覆盖复杂截面/曲线、重复凹齿、密集齿形、复杂孔槽、分层及多轴孔、弯管、多构件、局部凸起、截面突变、浅凹文字等原规则；不使用另写的LLM复杂度规则或置信度门槛。原始强规则/扩展规则至少命中一项即为本维度“通过”，完整扫描无命中为“不通过”；保留原高召回筛选的误报/漏报局限。

原 Skill 需要同源内部图册和几何缓存，程序按原 `parts_pdf` 流程从当前STEP自动生成，只写入本次输出，不要求额外提交，也不将用户工程图当成内部图册。全部14个扫描器照常执行；源文件、原候选、命令和哈希可追溯。详见 [复杂特征维度说明](modules/module_01/dimension_02_complexity/README.md)。

尺寸只检查是否有标注，不评估尺寸是否齐全或正确。透视效果图、标题栏、同方向重复放大图不作为新增工程视图。

## 单独运行模块或维度

### 完整模块与单维度的区别

完整模块的三条独立运行命令和自动分类总入口统一放在 [首页运行步骤](../../README.md#3-准备输入并运行)，不需要先手动运行前置脚本。本节补充单维度和单文件用法。

`--dimension all` 为默认值，表示完整模块；`--dimension 1/2/3` 表示只评测该维度（模块三仅有1、2）。两种模式都自动执行前置及输入分类，区别在于单维度无论结果如何都不查重、不入库，不代表整套资料验收通过。

总入口单选维度：

```bash
bash run.sh --input-dir "/你的模块一输入目录" --module 1 --dimension 2 --llm off
bash run.sh --input-dir "/你的模块二输入目录" --module 2 --dimension 2 --llm off
```

也可以进入对应维度目录，直接运行本目录脚本（仍检查整套输入、仍不能绕过前置）：

```bash
cd modules/module_01/dimension_02_complexity
bash run.sh --input-dir "/你的模块一输入目录"
```

目录对应关系：

```text
modules/
  module_01/
    dimension_01_correspondence/  文件配套及内容
    dimension_02_complexity/      复杂特征
    dimension_03_drawing_quality/ 尺寸及视图
  module_02/
    dimension_01_correspondence/  两目录文件配套及内容
    dimension_02_quantity_ratio/  去重数量及占比
    dimension_03_membership/      非标准件属于总装
  module_03/
    dimension_01_correspondence/  STEP/STP提供性（保留旧目录名兼容入口）
    dimension_02_unique_count/    去重数量
```

每个模块和每个维度下都有 `run.sh`、`evaluate.py`、说明；维度的业务判定在 `checker.py`，共享的解析、证据准备和AI接口在 `common/`。

### 显式指定单个文件

单个文件也可显式指定，自动识别模块一或三。下面仅测试模块一第一维度，不入库：

```bash
bash run.sh --step "/路径/零件.step" \
  --solidworks "/路径/零件.sldprt" --drawing "/路径/零件.pdf" \
  --module 1 --dimension 1 --llm auto
```

`--solidworks` 可重复指定，只与 `--step` 同用；显式输入只检查明确提交的文件，不自动加入同目录中的 SolidWorks 文件。使用 `--input-dir` 时递归发现，无需另传 `--solidworks`。模块三只需 STEP，无需 `--drawing` 或 `--solidworks`，例如单独测试第一维度：

```bash
bash run.sh --step "/路径/总装.step" --module 3 --dimension 1 --llm off
```

完整运行模块三时去掉 `--dimension 1`，或指定 `--dimension all`。整个模块三在 `--llm auto` 或 `off` 下均不调用 AI，不需要配置 AI 密钥；完整通过后仍会查重入库，试跑请指定查重库副本。

## API 配置与常见问题

以下命令均在 `project/aichecker_new` 目录执行，并使用已安装依赖的 Conda 环境。模块一、二的视觉项需要 API；模块一复杂特征、模块二数量及占比、模块三全部检查不需要 API。模块三可以跳过配置直接使用 `--llm off`。

### 配置位置与接口协议

首次创建配置的命令和完整 JSON 示例统一放在 [首页 API 配置步骤](../../README.md#2-配置-api)。这里说明读取规则及接口要求。

配置的两个字段为 `base_url`（HTTPS API 地址）和 `api_key`（密钥本身，不加 `Bearer `）。模板空值和文档占位值都不能用于真实请求，程序会自动添加认证头。默认配置位于本项目的上一级 `project/key.txt`，不随启动终端所在目录变化；自定义相对路径则相对于当前工作目录。用 `--llm-config "/你的配置目录/key.txt"` 可指定包外文件。

接口必须满足本项目当前协议：HTTPS、Bearer 认证、Chat Completions、`image_url` 中的 PNG base64 图片输入，并支持指定的视觉模型。程序发送 `model`、`messages`、`temperature: 0`、`max_tokens: 16000`；返回需包含 `choices[0].message.content` 和完整结束标记 `finish_reason: "stop"`，其中内容是符合提示要求的 JSON。并非有一个 API Key 就一定兼容。

地址填写规则：

- `https://api.example.com/v1` 会请求 `https://api.example.com/v1/chat/completions`。
- `https://api.example.com/v1/chat/completions` 会直接请求该地址，不重复追加。
- 程序不会自动补 `/v1`。提供方使用其他前缀时，按其实际 API 路径填写；不要填网页聊天地址。
- 不接受 HTTP、地址中的用户名/密码、查询参数、片段或重定向；请填写不含这些内容的最终 HTTPS API 地址。

为兼容旧配置，也支持 HTTPS 地址与独立的 `Key: 密钥` 行；首次配置推荐上面的 JSON。不要把真实密钥写入命令、提交仓库或发给他人；报告不回显密钥、原始接口响应或服务地址。重新打包前必须排除自己的 `key.txt`。

### 模型、预算和完整命令

默认模型是 `volcengine/deepseek-v4-1-flash-260910`。接口提供方需要允许调用这个精确标识，并支持图片输入；不同服务的模型标识可能不同，按实际授权型号用 `--model` 覆盖。配置只读取 `base_url`、`api_key`，添加 `model` 字段不会切换模型；也不会自动读取 `OPENAI_API_KEY` 等环境变量作为替代配置。

以下是模块一第一维度的试跑；准备一个有效单零件 STEP/STP、至少一份 SolidWorks 和一份对应 PDF/DXF，替换输入路径，若更换接口也相应修改模型标识：

```bash
bash modules/module_01/run.sh \
  --input-dir "/你的模块一输入目录" \
  --dimension 1 \
  --llm auto \
  --llm-config "../key.txt" \
  --model "volcengine/deepseek-v4-1-flash-260910" \
  --max-llm-calls 4 \
  --llm-timeout 120
```

这会在前置检查及文件配套通过后实际发送图片和证据，可能产生费用；不是纯配置检查。单维度不查重、不入库。看终端给出的 `summary.md` 和对应维度的 `report.md`，调用次数见 `summary.json`。前置失败、没有配套资料或输入被分类为其他模块时，可能尚未调用 API；0 次请求不能证明接口可用。图纸与模型不一致而“不通过”也不等于 API 连接失败，要看具体中文原因。

需要完整运行模块二时，例如：

```bash
bash modules/module_02/run.sh \
  --input-dir "/你的模块二输入目录" \
  --dimension all \
  --llm auto \
  --llm-config "../key.txt" \
  --model "volcengine/deepseek-v4-1-flash-260910" \
  --max-llm-calls 160 \
  --llm-timeout 120 \
  --dedup-registry "/你的测试目录/测试查重.json"
```

测试库须先按下方“最终查重入库”一节复制创建；完整通过会修改该副本，不存在的测试库不会自动创建。正式验收则指定统一正式库。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--llm` | `auto` | 允许需要 AI 的检查调用接口；`off` 禁用 AI，不能代替视觉检查通过 |
| `--llm-config` | 项目上一级的 `key.txt` | 指定包含地址和密钥的配置文件 |
| `--model` | `volcengine/deepseek-v4-1-flash-260910` | 请求使用的模型标识，不会从配置文件读取 |
| `--max-llm-calls` | `40` | 整次运行共享的请求次数上限；`160` 是上限，不是固定消耗，也不是 token 上限 |
| `--llm-timeout` | `120` 秒 | 每次网络请求的超时设置，不是整个检测流程的时长上限 |

### 常见问题怎么排查

以下是排查方向，不是对错误原因的确定诊断。程序有意不回显敏感响应，HTTP 错误的具体解释需结合提供方控制台确认。

| 报告或现象 | 建议检查 |
| --- | --- |
| 配置 JSON 解析失败 | 使用英文双引号；不要有注释、末尾多余逗号或 Markdown 代码围栏 |
| 配置、网络请求或响应解析失败 | 先检查配置路径存在、两个字段非空、HTTPS 地址合法；再检查接口及响应结构兼容性。报告不会直接显示密钥 |
| HTTP 401 / 403 | 密钥是否有效、是否属于该服务、是否有模型权限；检查提供方的访问限制 |
| HTTP 404 | 是否误填网页地址、缺少路径前缀、拼错 `/chat/completions`，或模型标识不被该服务识别 |
| HTTP 400 / 422 | 核对模型是否支持图片、请求参数及输出上限是否兼容；本程序固定请求 `max_tokens: 16000`，没有同名 CLI 开关 |
| HTTP 429 | 检查服务限流、额度或并发限制；增加 `--max-llm-calls` 不会解决服务端限流 |
| HTTP 5xx / 网络连接失败 | 检查服务状态、网络、代理、DNS、TLS 证书和最终地址；不要用关闭证书验证来绕过问题 |
| 模型请求超时 | 核对网络和服务响应时间，可改为 `--llm-timeout 240` 后重新运行；失败请求不会自动重试 |
| 本次 AI 调用预算已用尽 | 确认输入规模后调高 `--max-llm-calls`，例如160，再重新运行；不能拼接两次结果完成入库 |
| 回答被截断 / 响应 JSON 解析失败 / 判断证据不完整 | 检查模型和接口是否符合协议、图纸是否清晰、资料是否完整；调整请求次数或网络超时不会增加单次输出 token 上限。这类项为“无法判定”，不会假通过 |
| AI 调用次数为0 | 检查是否为 `--llm off`、模块三或其他纯代码维度；也可能是前置、分类或文件配套已拦截，尚未到 AI 阶段 |

模块三即使 `--llm auto` 也不会读取密钥或调用 AI，不能用它测试 API 连通性。API 问题与 CAD 不合格要根据报告区分；“无法判定”不等于“通过”。

## AI、去重与边界

AI收到的是本地生成的STEP多视角图片、PDF/DXF渲染图片、提取文字及结构化几何证据，而不是声称直接看懂STEP原文。每个模型提供两张合图，覆盖六个正交方向和两个等轴测方向；用Numba加速的CPU逐像素深度遮挡渲染，避免内部面错误透出。开启AI会把这些资料发送到配置的服务地址。文件内容只作为不可信资料，不能指挥程序执行命令。

内容核对还会提供单位转换到毫米后的实际轴向尺寸、圆柱面轴向/半径分组等证据，避免只看归一化图片而忽略比例不同。轴向包围尺寸对曲面极值是网格近似，不能代替制造尺寸检测；圆柱面数量不是孔数，圆柱面也可能是外圆凸台。复杂特征独立使用原 Skill 的完整组合规则；不新增“只要两个孔轴方向就通过”等简化规则。

`--llm off` 禁止调用AI，模块一、二需视觉判断的项输出“无法判定”，不是假通过。模块一复杂特征、模块二数量/占比以及模块三全部维度可在证据完整时离线判定，复杂特征和模块三不受 `off/auto` 或LLM预算影响。请求预算和网络超时参数见上表；预算耗尽后未查完的AI项仍为“无法判定”。

该推理模型每次请求设置16000输出token上限，推理与最终JSON共享该上限；这是上限，并非固定消耗。响应截断不重试、不缓存为结论；网络或格式问题也不会当成通过。

几何去重精确复用 `scale_cad_v2/parts_pdf/scripts/mechanical_families.py` 的原始 `mechanical-seven-v2`：七项旋转/平移不变指标、1%对称容差、完整链接聚类。源码来源和哈希见 `vendor/PROVENANCE.md`。这是一种机械几何近似分族规则，不是零件身份的数学证明；同指标异形件、遮挡的内部结构、过小文字可能需要更丰富输入，不能保证AI百分之百正确。

每个STEP上限256MiB、200万实体；单次AI最多16张PNG及32MiB图像，结构化证据10万字符。图纸默认整次最多200页；超限未完整读取会报告无法判定，不按残缺证据通过。AI视觉判定要求结构化证据完整且模型自评置信度≥0.85；该分数不是经标定的实际准确率，且不用于复杂特征维度。

## 输出与退出码

每次写入新的 `outputs/run_时间_随机编号/`，终端最后打印报告路径。可用 `--output-dir` 指定空目录，但不得与输入重叠或覆盖已有结果。

- `summary.md`：中文总览。
- `summary.json`：结构化汇总，含AI调用次数。
- `preflight/`：原始STEP前置报告。
- `module_0N/dimension_*/report.md`、`report.json`：逐维度结论和证据。
- `geometry.json`、`context.json`、几何/图纸图片：可追溯的解析证据。
- `finalization/report.md`、`report.json`：最终查重入库结果；总览还会标明完整验收通过、重复拒绝、检查未完成或仅单项评测。

通过时结果为“通过”；不通过时给中文原因；证据不足为“无法判定”；前置拦截为“未执行”。完整模块运行退出0表示全部维度通过且最终查重入库成功；重复文件即使各维度通过，仍退出1。退出1也用于不通过/无法判定/前置拦截，退出2为运行或入库错误。单维度通过仍退出0，但明确标记“仅单项评测，未入库”，不代表完整验收成功。

## 最终查重入库

继续使用原来的 `bash run.sh --input-dir ...` 完整运行即可，不需要另执行入库命令。程序最终直接调用交接包根目录中的 `step_sha256_dedup.py`，共用同目录的 `step查重.json`：

- 模块一、模块三：查输入的唯一STEP/STP文件。
- 模块二：只查总装目录中的唯一总装STEP/STP，不登记非标准件文件或图纸。
- 本模块前置、分类及所有维度全部通过：计算通过检查的STEP编码并查库；已有相同SHA-256时输出中文拒绝理由和已有记录，不重复写入；没有时记录SHA-256、文件路径/字节数、所属模块、运行标识和时间。
- 有不通过、无法判定、运行错误、未执行或缺失的维度：不查重、不入库。`--llm off` 不会绕过需AI的维度；历史单维度报告也不能代替本次完整验收。

这仍是原脚本的**文件字节查重**：改文件名或移动位置不改变编码；重新导出后字节不同，即使几何相同，也不保证被识别为重复。不要与模块内部的几何零件去重混淆。

原脚本保留旧数据集扫描功能，新增单文件事务接口供本工具调用；日常使用总入口即可，**不要无参数运行原查重脚本来处理新提交**。完整模块通过后会修改当前指定的查重库，默认是随包快照；第二次提交同一文件会被拒绝。正式部署用 `--dedup-registry` 指定统一正式库，各人副本不会自动同步。

模块三已不依赖 AI，因此 `--llm off` 不会阻止完整通过后的查重入库。只想验证文件提供性可选 `--dimension 1`；完整模块试跑请使用下面的测试库副本。

并发查重通过 `<查重库>.lock` 保护，新增前备份原库到 `<查重库>.backups/`，使用同目录临时文件原子替换；既有记录保留。缺库、库损坏或不完整时报告错误，不会擅自重建空库或放行。备份位置写入终检报告。

取得查重锁后及提交前会再次核对整套输入；等待期间图纸、SolidWorks、非标准件或目录文件集合发生变化也取消入库。运行期间请勿编辑输入资料。SolidWorks 的文件哈希仅用于输入变化保护，不代表已经核验其 CAD 内容。

如果只想试跑完整模块，请先复制正式库，再明确指定副本：

```bash
# 首次创建测试副本；避免覆盖已有测试库。
cp -n "../../step查重.json" "/你的测试目录/测试查重.json"
bash run.sh --input-dir "/你的输入目录" --dedup-registry "/你的测试目录/测试查重.json"
```

指定副本后，完整通过的新文件只登记到该副本，不污染正式库。只测某个维度（`--dimension 1/2/3`）不访问查重库，无需副本。

## 代码入口与测试

安装步骤统一见 [交接包首页](../../README.md#1-安装运行环境)。历史输出、开发过程文档和业务测试 CAD 未随包发送。维护时建议按以下顺序阅读，不必先遍历旧项目依赖：

3. [前置调用](common/preflight.py)、[证据准备](common/context.py)、[几何分析](common/geometry_worker.py)、[视觉接口](common/vision.py)。
4. [最终入库条件](common/finalization.py) 与包根目录的 [查重脚本](../../step_sha256_dedup.py)。
5. [原始依赖说明](../scale_cad_v2/README.md)：仅保留复杂特征及其证据生成所需的四个组件；几何去重的源码来源另见 [vendor/PROVENANCE.md](vendor/PROVENANCE.md)。

在已激活环境的项目目录中运行：

```bash
python -m unittest discover -s tests -v
bash run.sh --help
```

私有业务 CAD 未随包发送，依赖它的一项测试会明确跳过；其他测试包含现场生成的几何与临时库，不读真实密钥、不向正式库登记。更重的36孔正例是 `tests/integration_original_complexity.py`，需要完整 FreeCAD/Blender/Swift 环境和一个尚不存在的输出目录。

也可通过 `AI_CHECKER_PYTHON=/完整路径/python bash run.sh ...` 选择已安装全部依赖的解释器。FreeCAD必须可在该Python中加载；它不是普通pip包，不应只安装PyPI同名包代替。

复杂特征另需原 `scale_cad_v2` 项目、macOS Swift/Vision（原OCR）和Blender。本包不附Blender应用和安装包；打包验证使用Blender4.5.7。新机器安装Blender后可传 `--blender "/路径/Blender"`，项目原源码路径可用 `--complexity-source` 调整；`--complexity-timeout 1800` 控制本项完整流程超时。本复杂特征运行阶段不下载依赖、不调用AI。
